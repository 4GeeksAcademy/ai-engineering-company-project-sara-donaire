# Development Rule

**Scope:** Always active for code changes in this repository.

- Keep each change focused on the requested behavior and follow the conventions of the surrounding code.
- For behavior changes, add or update focused tests that cover the changed behavior and important edge cases.
- Avoid unrelated refactors or formatting changes.
- For Nexova workflows, follow `CONTEXT.md` as the authority for current users, processes, systems, and needs; do not imply its legacy tools are integrated here unless the code proves it.
- Keep candidate screening as consultant decision support: use evidence tied to the vacancy, preserve human review, and do not automate candidate decisions or communications without explicit product requirements and approval.
